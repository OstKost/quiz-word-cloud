# МыслиВслуХ

Живое облако ответов на русском языке. Один ведущий, участники с телефонами, отдельный экран для проектора.

## Запуск

Нужен Node.js 24. Зависимостей нет.

```sh
npm run dev
```

Откройте http://localhost:3000. Для телефонов в той же Wi-Fi сети используйте IP компьютера вместо localhost. Сервер слушает порт 3000 на всех интерфейсах. Локальная база SQLite: `/tmp/slovopotok.sqlite`; задайте `DB_PATH` для постоянного пути. `PORT` меняет порт.

Создайте комнату, сохраните секретную ссылку ведущего и нажмите «Начать». Участникам покажите QR-код, отправьте ссылку через кнопку копирования или покажите шестизначный код. QR-код есть в панели ведущего и на большом экране. Для телефонов в Wi-Fi откройте страницу ведущего по IP компьютера, чтобы QR-код содержал доступный им адрес, а не localhost. «На большой экран» открывает облако без управления. Пауза сохраняет остаток времени, стоп закрывает приём. Новый вопрос очищает облако для следующего раунда. Скрытие блокирует слово до следующего раунда.

## Проверки и сборка

```sh
npm test
npm run build
node scripts/validate-artifact.mjs
```

Альтернативная сборка для Cloudflare Worker + D1: схема в `drizzle/0000_rooms.sql`, привязка `DB` в `.openai/hosting.json`. Сборка включает HTML и JavaScript в один Worker. Источник UI — `public/index.html`, API — `worker/index.js`, анимация — `public/cloud.js`, локальный HTTP/SSE — `scripts/local-app.mjs`. Не редактируйте `dist`.

Лимиты проверяются атомарным SQL: 1–10 ответов на идентификатор браузера, не чаще одного в секунду, повтор от одного участника не увеличивает популярность. Регистр, пунктуация и ё/е объединяются. Максимум 3 слова и 80 символов. Настройка фильтра проверяется сервером; словарный фильтр не распознаёт все возможные обходы. Очистка хранилища браузера создаёт нового участника; идентификация без регистрации не гарантирует уникальность человека.

Облако отображает до 200 самых популярных слов; все принятые ответы остаются в базе. Размер не ниже 14 CSS px; для плотного облака шкала роста уменьшается. При очень маленьком экране физическая вместимость ограничена. Анимация использует canvas и requestAnimationFrame: компактная спиральная композиция вокруг центра, горизонтальные и вертикальные слова, мягкие повороты, дыхание размера, пружинный рост и пять вариантов появления. Повернутые границы текста учитываются при столкновениях. Композиция пересчитывается через растровую сетку занятости, а кадры с неразрешённым пересечением не отрисовываются до устранения наложения. Локальный сервер отправляет ответы сразу через SSE; резервное обновление — раз в 180 мс. На паузе и после стопа постоянное движение прекращается. После изменения серверного кода перезапустите npm run dev. Предпочтение уменьшения движения поддерживается.

Секрет ведущего находится во фрагменте URL и отправляется только в заголовке авторизации для управляющих запросов. Не пересылайте эту ссылку участникам. Публичные ответы не включают секрет.

## Production и CI/CD

Адрес: https://quiz.ost.wang. Сервер: `176.53.174.118`, OpenResty проксирует на `127.0.0.1:18082`. Приложение работает в Docker на Node.js 24, SQLite хранится вне контейнера в `/opt/quiz-word-cloud/data/quiz.sqlite`.

GitHub Actions (`.github/workflows/ci-cd.yml`) проверяет каждый PR: тесты, сборку Worker, проверку артефакта, конфигурацию деплоя и запуск production-контейнера. Push в `main` после успешных проверок автоматически разворачивает эту версию. Для повторного деплоя используйте Run workflow на `main`. Node.js 24 соответствует [документации SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html); настройка Actions использует [setup-node](https://github.com/actions/setup-node).

В GitHub настроены секреты `DEPLOY_SSH_KEY` и `DEPLOY_KNOWN_HOSTS`. Ключ принадлежит отдельному пользователю `quiz-deploy`: SSH разрешает только `deploy <commit SHA>`, без интерактивной оболочки, туннелей и SCP. Архив исходников передаётся по stdin; сервер собирает образ и ждёт успешного healthcheck `/healthz`. Одновременные деплои блокируются. Обновление кратковременно разрывает SSE-соединения; клиент переподключается.

Серверные файлы:

- `/usr/local/sbin/quiz-deploy` — root-owned копия `deploy/deploy.sh`.
- `/usr/local/sbin/quiz-ssh-command` — root-owned копия `deploy/ssh-command.sh`.
- `/opt/quiz-word-cloud/compose.yml`, `.env`, `current` — текущая версия.
- `/opt/quiz-word-cloud/releases/<SHA>` — исходники релиза.
- `/opt/quiz-word-cloud/backups/` — согласованная копия SQLite перед каждым обновлением.
- `/opt/om/nginx/conf/sites/quiz-word-cloud.conf` — конфигурация домена (`deploy/openresty.conf`).

При неудачном healthcheck автоматически возвращается предыдущий образ и Compose-файл. База при откате не заменяется: новые ответы сохраняются. Изменения схемы должны оставаться совместимыми с предыдущей версией; автоматических миграций пока нет. Резервные копии находятся на том же сервере; для защиты от потери сервера нужны внешние копии. Образы, исходники и backup-файлы автоматически не удаляются.

Диагностика через SSH администратора:

```sh
cd /opt/quiz-word-cloud
docker compose ps
docker compose logs --tail=100 app
curl --fail http://127.0.0.1:18082/healthz
```

Ручной откат (выберите SHA уже собранного релиза):

```sh
cd /opt/quiz-word-cloud
printf 'RELEASE=%s\n' <SHA> > .env
docker compose up -d --wait --wait-timeout 120
printf '%s\n' <SHA> > current
```

После изменения серверных deploy-скриптов администратор должен установить их отдельно; workflow не перезаписывает доверенную SSH-команду. Для OpenResty используйте `openresty -p /opt/om/nginx/ -t` и затем `openresty -p /opt/om/nginx/ -s reload`.

HTTPS выдаётся Certbot через webroot `/var/www/letsencrypt`, обновление выполняет системный timer Certbot с reload OpenResty. Конфигурация домена находится в каталоге сайтов OpenResty Manager.
